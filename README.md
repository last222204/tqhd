# TQHD 전략 사이트

지금 이 순간 뭘 해야 하는지(☀️ 낮 / 🌙 밤 / 🏹 사냥)를 보여주는 한 페이지. 기준 문서는 [TQHD_SITE_SPEC.md](TQHD_SITE_SPEC.md) 하나다.
입력 기능은 없고, 기록은 GitHub Actions 가 매일 자동으로 쌓는다.

## 구조

| 파일 | 하는 일 |
|---|---|
| `index.html`, `assets/` | 화면 (바닐라 HTML/CSS/JS, 빌드 없음). GitHub Pages 가 저장소 루트를 그대로 보여준다 |
| `assets/core.js` | 판정 규칙 + 화면 내용 계산 (DOM 없음, 테스트가 같은 파일을 V8 로 돌린다) |
| `assets/config.js` | 실시간 프록시 주소 한 줄 |
| `scripts/tqhd.py` | 판정 규칙 (파이썬 쪽, core.js 와 같은 공식) |
| `scripts/update_state.py` | 매일: 시세 → `data/state.json`, `data/history.csv`(덧붙이기만), `data/prices.csv` |
| `.github/workflows/update.yml` | 매일 한국시간 07:00 (UTC 22:00) 실행 → 검사 통과하면 커밋 |
| `worker/` | Cloudflare Workers 실시간 프록시 (`GET /quotes`: QQQ·TQQQ·NQ=F·USD/KRW, CORS, 25초 캐시) |
| `tools/dev_server.py` | 로컬 미리보기 (사이트 + 프록시와 같은 일을 하는 /quotes) |
| `tools/check_proxy.py` | 프록시 연결 테스트 |

## 판정 (코드에 이대로 들어 있음)

- 낮: QQQ 종가가 50일선 **또는** 200일선 위 (**같으면 위**) → TQQQ 100%
- 밤: 둘 다 아래 → 현금
- 사냥: 밤인 날 RSI2 < 15 → 50%, < 5 → 100%. 사냥 중 50% 였다가 RSI2 < 5 가 되면 100% 로 늘린다
- 사냥 중 RSI2 > 50 → 전량 매도(밤). 사냥 중 선 회복 → 청산 없이 낮. 시간 제한 없음
- 경계: RSI2 정확히 15·5 는 진입 아님, 정확히 50 은 청산 아님
- RSI2 = Wilder(기간 2), 첫 평균은 처음 두 변화의 단순평균. 가격은 **배당조정 종가**(yfinance 기본값)
- 장중: 50일선 = (직전 49일 합 + 현재가)/50, RSI2 = 직전 Wilder 평균에서 한 걸음. 임계 가격은 닫힌 식으로 역산

## 화면이 바뀌는 때

| 때 | 맨 위 |
|---|---|
| 장중 | 지금 상태(실시간) + 어제 종가 확정 상태, 다르면 빨간 상자 |
| 장 마감 ~ 07:00 기록 전 | 오늘 종가 기준 상태 (기록 대기) |
| 주말·휴장일·장 시작 전 | 휴일 갭 카드: NQ 변화율 → QQQ 예상 시가 → 예상 상태·RSI2 |
| 프록시 실패 / 값 멈춤 | 회색, "실시간 연결 끊김, 전일 종가 기준만 유효" / "데이터 멈춤 · 마지막 갱신 시각" |
| Actions 멈춤 | "기준 데이터가 멈췄습니다" + 지금 상태 계산 안 함 |

## 검사

```bash
python -m pytest
```

- 검증 1 RSI2 손계산 값, pandas 독립 구현과 300일 대조
- 검증 2 파이썬 ↔ JS: 최근 60거래일 전부 이동평균·RSI2·상태·임계 가격 오차 1e-9 이내
- 검증 3 경계값: 선과 같음 = 낮, 둘 다 아래 = 밤, 한쪽만 위 = 낮, 상태 전환 표
- 검증 4 임계 가격 왕복: 그 가격 바로 아래/위에서 정말 상태가 바뀌는지 (파이썬·JS 둘 다)
- 검증 5 프록시 실패·값 멈춤·선물 휴장·Actions 멈춤일 때 옛 값을 현재가로 안 보여주는지
- 프록시: 실제 야후 응답을 워커와 로컬 쌍둥이가 똑같이 읽는지, 한 종목 실패해도 나머지는 오는지
